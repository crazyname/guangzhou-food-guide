# 收藏录入与核实规则

## 1. 字段与组织

- 每个小红书笔记按 **笔记 ID** 存放到 `data/notes/<note-id>.json`，对应 `notes/<note-id>.md`；README 维护可浏览的收藏索引。
- 店铺字段：品牌/店名、具体分店、广州行政区、商圈、详细地址、地图链接、类别、**人均人民币**、价格依据、营业时间。
- 推荐字段：推荐饮品或菜品、点单组合、原作者的主观评价、个人评分（仅亲自探店时填写）。
- 溯源字段：平台、作者、分享链接、原笔记 ID、发布时间（可知时）、采集日期、能直接核实的证据。
- 状态使用“想去 / 已去 / 推荐 / 不再考虑”，另记录“是否亲自探店”和各字段核实状态。

### 品牌—分店—笔记（仅广州）

- 每个品牌在 `brands/` 和 `data/brands/` 各有一份档案，**分店只保留广州市行政区内的门店**，外市不入库。
- `data/brands/*.json` 的每条分店均以单独 `branch_id` 保存，明确行政区、商圈、准确门牌或仅商场地址、价格与核实来源；品牌范围及是否已覆盖全部门店应单独标注。
- 原始笔记在 `notes/` 和 `data/notes/` 保存，关联明确的分店；仅有品牌级推荐时不能强行指定某家分店。
- 商场地址不等于店铺门牌；同一品牌不同分店的营业时间、人均、菜单、评价、排队情况不能复制。
- 对名称类似但经营品类后缀不同的门店，仅在确证属于同一品牌体系后合并；此前作为**关联待核实线索**保留。

## 2. 必须区分已证实与未知

- **原始笔记**：按原作者实际写法摘录推荐组合，标注“博主推荐”；不把情绪词当品牌名，不把自己的猜测写成商家事实。
- **店名与地址**：优先核对笔记地点标签、商家官方信息、地图上的同名分店。仅有杯身印字、配色、产品外观时不直接认店。
- **价格与人均**：优先以该分店大众点评/美团商户页的人均数据、门店菜单、实际付款或注明日期的商家平台页面为依据。人均、品牌产品单价、单品售价、平台价位区间是四种不同字段，不能混用；无法核实时 JSON 写 `null`、页面写“待核实”。
- **大众点评来源**：仅在确认同城同品牌同分店、可打开准确的商户页面时才记录其评分/人均/商户 ID。只能找到报道中引用大众点评评论时，标注“间接引用”，不要冒充直接读取。页面访问受限时注明查找时点及限制。
- **评价**：原作者观点和收藏者探店体验独立记录；分享一条笔记不代表收藏者已去过。
- **发布时间**：不拿手机截图时间、笔记分享时间冒充发布日期。
- **证据缺失**：网页需要登录、链接失效或无法读取时，写明限制和已验证的部分，绝不虚构地址、门店、人均或营业时间。

## 3. 去重与更新

1. 优先根据原笔记 ID 去重；同一链接重复分享，只补充新证据，不新增记录。
2. 不同笔记提及同一家店时，先确认**品牌及具体分店**，再按门店聚合推荐；品牌相同的不同分店不直接合并价格及地址。
3. 每次变更 README 索引、Markdown 详情和 JSON 字段，保持三者一致。
4. 变更已证实字段时，保留证据链接或核实日期，并说明修正来源。

## 4. 来源访问与合规

- 优先读取分享链接能公开访问的笔记信息和用户提供的截图，保留原链接与笔记 ID。
- 正文、图片或店铺位置若需要登录或授权，只能通过合法、受授权的访问方式取得；不得把账号 Cookie、密码、访问令牌或含个人信息的链接参数提交到公开仓库。
- 不复制无授权的整篇笔记或整套图片进仓库，仅保存用于私人索引的必要结构化事实及简短推荐摘要。
